System Documentation & Developer Guidelines: Paymerch Mobile 

Tagline: Simply Secure Payments 

Part 1: End-to-End Product & Technical Documentation 

1. Product Overview 

Paymerch Mobile is a phone-to-phone digital wallet and payment application designed for micro-traders, street vendors, and public transport operators in informal economies. The app allows users to make and receive payments, purchase value-added services (VAS) like airtime and electricity, and manage digital funds using single-use Dynamic QR Codes. 

2. Architecture & Transaction Flow 

The platform uses a buyer-initiated dynamic QR model to ensure hardware-free execution and eliminate static placard overcharge risks. 

+-------------------------------------------------------------------------+ 
|                               BUYER APP                                 | 
|  1. Inputs Amount / Selects VAS Item                                    | 
|  2. Authenticates via PIN / Biometrics                                  | 
|  3. Fetches Signed Token -> Renders Dynamic QR Code                     | 
+------------------------------------+------------------------------------+ 
                                     | 
                                     | Scans QR Camera Stream 
                                     v 
+-------------------------------------------------------------------------+ 
|                             MERCHANT APP                                | 
|  1. Reads QR Payload (JSON Token)                                       | 
|  2. Attaches Merchant_ID + Device Signature                             | 
|  3. Submits Request to Paymerch Core API (TLS 1.3)                      | 
+------------------------------------+------------------------------------+ 
                                     | 
                                     | Signed API POST Request 
                                     v 
+-------------------------------------------------------------------------+ 
|                       PAYMERCH CORE BACKEND                             | 
|  1. Validates HMAC Signature & 60s Expiry Timestamp                     | 
|  2. Checks Buyer Ledger Balance >= Transaction Amount                   | 
|  3. Executes Atomic Ledger Shift (Debit Buyer / Credit Merchant)        | 
|  4. Flags Token as Consumed (Anti-Replay)                               | 
|  5. Emits WebSockets Push Notifications to Both Parties                 | 
+-------------------------------------------------------------------------+ 
 

3. Data Schema & Core Endpoints 

SQL Ledger Schema 

SQL 

CREATE TABLE wallets ( 
    wallet_id UUID PRIMARY KEY DEFAULT gen_random_uuid(), 
    user_phone VARCHAR(15) UNIQUE NOT NULL, 
    pin_hash VARCHAR(255) NOT NULL, 
    balance DECIMAL(12, 2) NOT NULL DEFAULT 0.00, 
    status VARCHAR(20) DEFAULT 'ACTIVE', 
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP 
); 
 
CREATE TABLE transactions ( 
    txn_id UUID PRIMARY KEY DEFAULT gen_random_uuid(), 
    sender_wallet_id UUID REFERENCES wallets(wallet_id), 
    receiver_wallet_id UUID REFERENCES wallets(wallet_id), 
    amount DECIMAL(12, 2) NOT NULL, 
    txn_type VARCHAR(30) NOT NULL, -- 'MERCHANT_PAY', 'VAS_ELEC', 'TOPUP' 
    status VARCHAR(20) NOT NULL,   -- 'SUCCESS', 'PENDING', 'FAILED' 
    signature_hmac VARCHAR(255) NOT NULL, 
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP 
);

4. Security & Offline Protocol 

Key Storage: Access tokens and session secrets are locked inside the Android Keystore or iOS Secure Enclave. 

Zero Local Balance: Wallet balances remain strictly on the backend; a stolen device exposes no funds. 

Store-and-Forward Caching: When offline, scans save to an encrypted local SQLCipher database. The app displays an Offline Pending notification and syncs via background workers once cellular network connectivity restores.
